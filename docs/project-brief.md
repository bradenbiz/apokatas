# Apokatas project brief

Recorded from the user's initial idea on 2026-09-12, with direction clarified on 2026-10-02. This is an idea inventory, not an approved specification or a set of implemented capabilities.

## Purpose

Create an open-source, gold-backed monetary system to bring gold and silver back as money and support what the user calls sound money. Other metals, specifically copper and platinum, were mentioned as possible additions. On 2026-10-02 the user clarified a preference for many contributors, independently hostable software and different operators running components. The exact governance, participation and monetary guarantees are still being discussed.

## Inspirations

The user named e-gold, Goldmoney, Kinesis, Tether Gold, Pax Gold, and "t-gold by Schiff Gold" as predecessors or competitors. The intention is to improve on where existing services fall short; the user has since identified repeated delays, scope complexity, unexplained incentive economics and dependence on one organization as priority concerns. These motivations and their evidence limits are recorded in the [rationale](rationale.md), with anonymized lessons in the research folder.

The [preliminary predecessor notes](research/predecessors.md) preserve early factual findings. They are not a completed competitive assessment or endorsements.

## Candidate features

1. Spot markets with simple trade execution.
2. Quick and easy fiat deposits and withdrawals.
3. Simple, timely, and affordable physical redemption.
4. Regular, frequent, and trustworthy audits of metal and fiat.
5. Free pooled storage and automated, affordable segregated storage.
6. Physical and digital debit cards.
7. Clean and intuitive interfaces.
8. Quality documentation and issue remediation.
9. Automated tax reporting.
10. Possible yields for stakeholders or token holders. The user is explicitly unsure about this and whether existing fee-sharing token models have been a good idea.

These are candidate capabilities, not commitments for the first release. The costs of free storage, the source of any yield, and the viability of the overall economics remain open. Mentioning tokens does not select a blockchain or token architecture.

## Initial operating preference

The user considers vertical integration unlikely to be practical initially and prefers exploring service providers for banking, vaulting, cards, and audits as a possible route to an MVP. On 2026-10-02 the user reinforced this direction: Apokatas need not own vaults, should explore gold/silver custody and tokenization as API services, and should favor replaceable providers. Broad provider compatibility is a long-term ambition; end-user provider selection is a candidate option. This is not a verified provider plan or an instruction to integrate every provider in the pilot.

Rush, BullionVault, Kitco Digital Metals, and nFusion were subsequently supplied as [unverified provider leads](research/provider-leads.md).

## Planning status

The assistant proposed a decision-complete design for a first viable pilot as the planning destination. The user has not accepted or changed that proposal. The [opening questions](planning/open-questions.md) now include partial user answers on openness and predecessor problems; destination, initial users and monetary guarantees remain unresolved before the map can be settled.
