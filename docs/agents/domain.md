# Domain documentation

Use a single project context unless the project later develops a demonstrated need for multiple contexts.

- Read `CONTEXT.md` for agreed domain language when it exists.
- Read relevant records in `docs/adr/` when they exist.
- Create these files only when an agreed term or a qualifying architectural decision needs to be recorded. Their current absence is expected.
- Keep `CONTEXT.md` a glossary. Put the feature inventory, unanswered questions, implementation detail, and history in their respective documents.
- Use architecture decision records for consequential trade-offs that are difficult to reverse and would be surprising without context.

Terms such as sound money, open, ownership, and the precise meaning of a metal balance are still under discussion. The current brief records the user's language without claiming those terms are settled definitions.
